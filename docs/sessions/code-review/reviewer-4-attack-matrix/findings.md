# Adversarial Review — Attack Matrix Grid

Date: 2026-07-10
Reviewer: reviewer-4-attack-matrix

## CRITICAL

1. **components/attack-matrix.tsx:53-144 — ARIA grid structure violation: no `role="row"` containers.** The `role="grid"` wrapper has 13 direct children (1 corner, 3 column headers, 9 cell wraps). The ARIA grid pattern requires every child of `role="grid"` to have `role="row"`, and every child of `role="row"` to have `role="columnheader"`, `role="rowheader"`, or `role="gridcell"`. Screen readers (NVDA, JAWS, VoiceOver) will not expose the 3x3 matrix structure; they will announce a flat list of 13 items, making it impossible for users to understand the bipartite attacker/target relationship.

2. **components/attack-matrix.tsx:89-100 — `aria-expanded` toggles on empty cells with no expandable content.** When a cell has `count === 0`, clicking it sets `aria-expanded="true"` (line 98), but the conditional `isExpanded && cellAttackList.length > 0` (line 114) prevents the expanded region from rendering. The ARIA contract for `aria-expanded` requires it to be `true` only when the controlled content is actually visible. This causes screen readers to announce "expanded" on an element that has nothing to expand, violating the ARIA Authoring Practices.

3. **components/attack-matrix.tsx:90-112 — No `aria-controls` association between button and expanded region.** The `<button>` toggles `aria-expanded` but the expanded `<div role="region">` (line 115) has no `id` and the button has no `aria-controls` attribute. Screen reader users cannot programmatically jump from the button to the expanded content. When the user activates a cell, the expanded cards appear visually below the grid but are completely disconnected from the button in the accessibility tree.

## HIGH

1. **components/attack-matrix.tsx:46-48 — Empty state guard is too coarse: filters out all data when `attacks.length === 0`, but does not handle "events present but no attacks match known teams."** If the SSE stream delivers attack events with `actorId` values not in `ATTACKER_TEAMS` (e.g., `judge-panel`, `artifact-writer`, or an unknown future team), the `attacks` array is non-empty, so the early return at line 46 is bypassed, but every cell filter (line 27) returns empty results. The user sees a full 3x3 grid of "No attacks from X to Y" cells. This is misleading — it implies no attacks exist, when in reality attacks exist but reference teams outside the hardcoded set. The grid should either show an "unknown teams" indicator or at minimum log a warning.

2. **components/attack-matrix.tsx:39-44 — Redundant keyboard handler on `<button>` causes potential double-activation.** The `<button type="button">` element natively handles Enter and Space (keyup) by firing `onClick`. The custom `onKeyDown` handler also fires `toggleCell(key)` for both keys. While `e.preventDefault()` on keydown for Space does suppress the native activation in most browsers, this is fragile and non-standard. The handler also fires `toggleCell` for empty cells (line 42), which sets `aria-expanded="true"` on a cell that has nothing to expand. The custom keydown handler should be removed or the button should be changed to a `div role="button"` with explicit keydown handling.

3. **components/attack-matrix.tsx:1685 (globals.css) vs component — CSS defines `.attack-matrix-row-header` (globals.css:1694-1704) but the component never renders any row header elements.** The grid is a bipartite matrix (rows = attackers, columns = targets) but row headers (attacker team names on the left side) are completely missing. The first column slot in the CSS grid (`140px`) is occupied only by the corner cell in row 1, and by self-attack diagonal cells in rows 2-4. Users cannot tell which row represents which attacker team from the visual layout alone. The 3x3 attacker/target relationship is ambiguous without row headers.

4. **app/battle/[id]/live/page.tsx:120-124 — Attack event filter may silently drop events if `round` naming convention shifts.** The filter `e.round === "cross_attack_round" && e.eventType === "attack_created"` is hardcoded to the exact string `"cross_attack_round"`. The `BattleRound` type in `lib/types.ts` uses `"cross_attack"` (with underscore, no `round` suffix), while `arena/schemas/types.ts` `BattleEvent.round` is `string` (untyped). If the engine ever emits `"cross_attack"` instead of `"cross_attack_round"`, all attack events are silently excluded from the matrix. The `ROUND_ORDER` array on line 66-75 uses `"cross_attack_round"` consistently, but the `deriveCurrentRound` function on line 77-80 returns the raw `events[last].round` value, so a mismatch between the timeline and the event filter is possible.

## MEDIUM

1. **components/attack-matrix.tsx:25-28 — `cellAttacksFor` runs 9 full array scans per render, O(n*9) for n attack events.** For a 3x3 grid with 3 teams, the filter is called once per non-self cell (6 times). With 100 attack events, that's 600 comparisons per render. The component re-renders on every new SSE event (parent re-render in `live/page.tsx`). A `useMemo` precomputing a `Map<string, AttackEventLike[]>` keyed by `"actorId->targetId"` would reduce this to O(n) per render.

2. **components/attack-matrix.tsx:39-44, 99-100 — Inline arrow functions create new closures on every render.** `onClick={() => toggleCell(key)}` and `onKeyDown={(e) => handleKeyDown(e, key)}` allocate new function objects for every cell on every render. With 6 non-self cells and frequent SSE updates, this causes unnecessary reconciliation work. Extracting to stable callbacks (e.g., `useCallback` with `key` dependency) or using a data attribute + event delegation would be more efficient.

3. **components/attack-matrix.tsx:88-112 — Cell `<button>` has no visible focus ring unless the CSS `:focus-visible` pseudo-class is matched (globals.css:1737-1741).** The `outline: 2px solid var(--ring)` with `outline-offset: -2px` works in modern browsers, but the `z-index: 1` is only applied in the focus-visible state. When the expanded content renders (line 114-139), it is a sibling inside the same `.attack-matrix-cell-wrap` (which has `display: contents` per globals.css:1707). Since `display: contents` removes the wrapper from the box tree, the expanded content becomes a direct grid child and may overlap with adjacent cells or extend beyond the grid border. The grid container has `overflow: hidden` (globals.css:1662), which could clip the expanded cards.

4. **components/attack-matrix.tsx:114-139 — Expanded region has no `aria-label` on individual cards beyond the region-level label.** Each `<article className="attack-matrix-card">` (line 117) has a `className` but no `aria-labelledby` or heading element. Screen reader users navigating the expanded content hear a series of `<article>` landmarks with no clear titles beyond the event ID `<span>` (line 120), which is not a heading. Adding a visually hidden heading or `aria-label` to each card would improve navigation.

5. **components/attack-matrix.tsx:62-68 — Column headers use `role="columnheader"` but lack `scope="col"`.** While `scope` is not strictly required when using ARIA `role="columnheader"`, the ARIA Grid Pattern recommends explicit `aria-colindex` or `scope` attributes for complex grids. More importantly, the headers contain a `<span aria-hidden="true">&rarr;</span>` (line 65) which is correctly hidden, but the visual arrow could be confusing to sighted users who wonder why an arrow points to a column header.

6. **components/attack-matrix.tsx:131-135 — Card footer shows `event.round` as a "time" label (`attack-matrix-card-time`).** The CSS class name says "time" (globals.css:1847) but the content is a battle round string (e.g., `"cross_attack_round"`), not a timestamp. This is a misleading label — the data is a round identifier, not a time. The `BattleEvent` type in `arena/schemas/types.ts` has a separate `createdAt` field (line 240) that would be more semantically correct for a "time" display.

7. **app/battle/[id]/live/page.tsx:618 — `<AttackMatrix attacks={attacks} />` passes filtered `BattleEvent[]` but the component expects `AttackEventLike[]`.** The structural types are compatible (both have optional `actorId`, `targetId`, `id`, `content`, `title`, `round`), but there is no explicit type assertion or interface contract. If the `BattleEvent` shape changes (e.g., `actorId` becomes required), TypeScript will catch the mismatch at the call site — but only if strict mode is enabled and the types are imported. Currently the live page imports `BattleEvent` from `@/arena` (line 21) and the matrix uses its own local `AttackEventLike` (line 6), so there is no shared type contract.

8. **components/passport-actions.tsx:33-43 — Print button has no keyboard activation feedback for `onClick`.** While `<button>` elements natively handle Enter/Space, the `onClick` calls `window.print()` without any user-visible confirmation or loading state. On slow devices, the user may click multiple times, queuing multiple print dialogs. This is a UX issue, not a functional bug.
