# UI Learnings

## 2026-07-25 · v0.5.2 中文主路径

- 实时入口必须直接锚定真实 Idea 输入区，避免“实时开战”把用户带到固定回放表单。
- Live Runtime 的降级不只是换一张卡；进入降级态时必须关闭 SSE，避免后台模型继续消耗资源。
- 移动端取证应记录真实 viewport 与页面级横向溢出断言；组件内部横向轨道可以保留。
- 中文优先不排斥团队英文代号和证据 ID，但动作、状态与错误信息必须以中文为第一视觉层级。

## 2026-07-25 · v0.5.2 独立产品审查

- 路由数量必须从真实 Router 配置核对；导航隐藏不等于旧页面已经移除。
- 自动化无横向溢出断言需与 Windows 可见滚动条环境复核，避免只依赖单一浏览器配置。
- “可演示”与“需求完成”应分开结论：真实模型进入诚实降级可保障演示，但不等于实时全流程成功。
- 像素级验收必须同时展示设计稿与同 viewport 实现图；只有实现截图不足以证明差异低于 5%。

## 2026-07-25 · v0.5.2 实时数据流与视觉闭环

- 实时思考区应展示可审计的工作摘要、观察和决策，不暴露原始 chain-of-thought；这些摘要必须作为事件持久化，刷新后可重建。
- 模型流式输出的 `finish_reason=length` 不能当作 schema 失败吞掉；按阶段提高 token 预算并有限重试，UI 继续用活动事件维持等待期反馈。
- 完成态 Artifact 的标题必须绑定 `champion_selected.winnerTeamId`，不能沿用最后一次攻击目标，否则内容与身份会自相矛盾。
- 正式视觉证据应在动画生命周期结束后取样；终态截图至少等待 Floating Damage 的 1100ms 卸载完成。
2026-07-26 · 冠军回放 · “返回竞技场”和“查看回放”不能共用完成态 URL；持久化实时 Battle 使用 `replay=1` 从事件 1 投影，且不重连 SSE。· 适用于结果页返回时间线。
2026-07-26 · 队伍作品 · 卡片入口必须把 teamId 一直带到 Proposal、Defense、Score、Test、Evidence 投影，不能在发现冠军 Artifact 后覆盖用户选择。· 适用于多参与者详情弹窗。
2026-07-26 · 冠军语义 · 非冠军 Mini App 标记为“队伍方案 · 交互验收”，只有 winner 可使用冠军作品标签；底部统一入口在裁决完成后指向 winner。· 适用于同屏多版本交付物。
